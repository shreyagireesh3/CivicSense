# Project Architecture Rules (Non-Obvious Only)

- **Strict pipeline dependency**: notebooks must run in numbered order. `01` → cleaned CSV; `03` → model files + forecast CSVs; `04` → insight CSV; `05` + `05_forecast` → dashboard JSONs.
- The analytics backend is **stateless and read-only** by design. No write endpoints, no DB, no caching. All JSON files are regenerated by rerunning the notebooks.
- The React app fetches all 14 analytics API endpoints in parallel on mount (`Promise.all`). No lazy loading — full dataset loads upfront. Adding a new endpoint means adding it to the `endpoints` array in `loadData()`.
- Adding a new analytics data dimension requires changes in **three places**: the generating notebook, the backend route in `main.py`, and `App.jsx` (fetch list + UI rendering).
- The frontend is a **single-page, single-file** app with no router. All views (Command Centre / Analytics / Forecasts / Insights / Service Desk) are rendered conditionally inside `App()` via `activeSection` state.
- `InsightsSection` is computed client-side from already-loaded API data via `buildInsights()`. The `/api/insights` endpoint exists but is not used for the UI insight cards — they are derived from categories/wards/forecast data.
- ML models: `HistGradientBoostingRegressor` with `TimeSeriesSplit(n_splits=4)`. Feature engineering and serialisation in `notebooks/03_predictive_analytics.py`. Forecast uses recursive 14-day rolling strategy.
- **Two venvs** at project root: `.venv-1` is production-correct (FastAPI + httpx + pytest). `.venv` is incomplete. The `uvicorn` and `pytest` commands must use `.venv-1`.
- **Service Desk** is architecturally separate from the analytics pipeline: `backend/desk.py` is a self-contained SQLite router mounted at `/api/desk`. It has no dependency on the notebook pipeline or `dashboard/public/data/`. `data/desk.db` is auto-created and is gitignored.
- The `_next_ticket_id()` function counts existing tickets for the current year to generate sequence numbers — concurrent inserts under load could produce duplicate IDs (not a concern for current single-user use).
